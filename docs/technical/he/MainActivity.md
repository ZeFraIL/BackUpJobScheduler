# תיאור מחלקה: MainActivity

## 1. מידע כללי
*   **שם המחלקה:** `MainActivity`
*   **סוג:** Activity (מסך ראשי)
*   **מטרה:** זוהי נקודת הכניסה לאפליקציה. האחריות העיקרית שלה היא לאתחל את האפליקציה ולהפעיל את תהליך תזמון הגיבוי ברקע.
*   **אינטראקציות:** היא קוראת למחלקה `BackupScheduler` כדי להגדיר את משימת הגיבוי.

## 2. משתנים (שדות המחלקה)
| שם | סוג | מטרה | היכן בשימוש |
| :--- | :--- | :--- | :--- |
| `TAG` | `String` | תווית המשמשת לרישום לוגים (הדפסת הודעות למפתחים). | ב-`Log.d` או `Log.e` כדי לזהות מאיפה ההודעה הגיעה. |

## 3. מתודות המחלקה
### שם המתודה: `onCreate`
*   **סוג:** `protected`
*   **ערך חזרה:** `void` (לא מחזירה כלום)
*   **פרמטרים:** `savedInstanceState` (`Bundle`) - מכיל נתונים מהפעלה קודמת.
*   **מה היא עושה:** 
    1. קוראת לגרסת ה-`onCreate` של מחלקת האם.
    2. מגדירה את העיצוב הוויזואלי באמצעות `setContentView`.
    3. קוראת ל-`BackupScheduler.scheduleBackup(this)` כדי להתחיל את לוגיקת הגיבוי ברקע.
*   **מתי נקראת:** באופן אוטומטי על ידי מערכת אנדרואיד בעת הפעלת האפליקציה.

## 4. מחזור חיים
*   **onCreate():** נקראת כאשר האקטיביטי נוצרת לראשונה. כאן אנחנו בונים את ה"שלד" של המסך ומפעילים את טיימר הגיבוי.

## 8. הסבר מפושט
**"הסבר במילים פשוטות"**
חשבו על `MainActivity` כעל **כפתור ההפעלה** במכונת קפה. כשלוחצים עליו, המכונה נדלקת ובודקת באופן אוטומטי אם היא צריכה להתחיל מחזור ניקוי (משימת הגיבוי). הכפתור עצמו לא מכין את הקפה; הוא רק מתחיל את התהליך.
