🎯 Цель проекта
•	**Какую задачу решает приложение:** Автоматизация процесса создания резервных копий локальной базы данных SQLite.
•	**Почему эта задача важна:** Предотвращение потери данных пользователя в случае сбоя приложения или устройства. Резервное копирование выполняется в фоновом режиме в заданное время.
•	**Целевая аудитория:** Разработчики Android-приложений, нуждающиеся в надежном механизме фонового сохранения данных.
________________________________________
📌 Требования к приложению
**Функциональные требования**
•	Планирование задачи резервного копирования при запуске приложения.
•	Выполнение копирования базы данных в фоновом режиме каждые 24 часа.
•	Сохранение файла базы данных в публичную директорию документов.
**Нефункциональные требования**
•	**Производительность:** Минимальное влияние на работу системы за счет выполнения задачи в часы низкой активности (01:00 ночи).
•	**Удобство использования:** Процесс полностью автоматизирован и не требует вмешательства пользователя.
•	**Надёжность:** Использование системного `JobScheduler` для гарантированного выполнения задачи даже после перезагрузки устройства.

🧠 Общая архитектура
•	**Выбранный подход:**
–	Структурный подход на базе компонентов Android (Service-Oriented).
•	**Почему выбран именно он:** `JobScheduler` является стандартным и эффективным способом планирования фоновых задач в Android, обеспечивающим баланс между потреблением энергии и выполнением работы.
•	**Основные компоненты системы:**
–	`MainActivity`: Точка входа, инициирующая планировщик.
–	`BackupScheduler`: Класс для конфигурации и запуска `JobInfo`.
–	`BackupJobService`: Сервис, выполняющий непосредственное копирование файла.
–	`HelperDB`: Класс для управления базой данных SQLite.

🧩 UML-диаграмма (обязательно)
`[MainActivity]` –> `[BackupScheduler]`
`[BackupScheduler]` –> `[BackupJobService]` (через JobScheduler API)
`[BackupJobService]` –> `[HelperDB]` (доступ к файлу БД)
`[BackupJobService]` –> `[External Storage]` (сохранение копии)

**Объяснение:**
- Разделение ответственности: логика планирования отделена от логики выполнения.
- Это помогает масштабированию: легко добавить новые типы фоновых задач без изменения основного интерфейса.

🧩 Подробное описание классов
📌 **Класс: MainActivity**
**Роль:** Главная активность приложения.
**Ответственность:** Инициализация интерфейса и запуск планировщика задач.
**Основные методы:**
- `onCreate()` — устанавливает макет и вызывает `BackupScheduler.scheduleBackup()`.
**Взаимодействие с другими классами:** Вызывает статический метод `BackupScheduler`.

📌 **Класс: BackupJobService**
**Роль:** Фоновый сервис (JobService).
**Почему используется:** Позволяет системе выполнять работу в фоне согласно заданным условиям (сеть, зарядка).
**Ответственность:** Копирование файла БД в отдельном потоке.
**Основные методы:**
- `onStartJob()` — запускает поток для копирования.
- `backupDatabase()` — реализует логику FileChannel transfer.

📌 **Класс: BackupScheduler**
**Роль:** Конфигуратор задач.
**Ответственность:** Настройка периодичности (24 часа) и условий (наличие сети) для JobScheduler.
________________________________________
🔄 Диаграмма работы приложения
**Сценарий:**
1. Пользователь открывает приложение.
2. `MainActivity` просит `BackupScheduler` запланировать работу.
3. Система Android ставит задачу в очередь.
4. В 01:00 (или при выполнении условий) система запускает `BackupJobService`.
5. Сервис создает поток, копирует `all_cars.db` в папку `Documents/DatabaseBackups`.
6. Сервис сообщает системе об окончании работы.

⚙️ Работа с потоками
**Опишите:**
- Используются: `Thread` (внутри `BackupJobService`).
•	**Почему выбран этот способ:** Простое копирование файла не требует сложных механизмов реактивного программирования, достаточно базового потока для освобождения Main UI Thread.
•	**Как предотвращаются:**
–	Зависания (ANR): Операция ввода-вывода вынесена из главного потока.
–	Утечки памяти: Короткоживущий поток, завершающийся вместе с задачей.
________________________________________
💾 Работа с данными
•	**Где хранятся данные:** SQLite (внутренняя память) и резервные копии (внешняя память).
•	**Почему выбран этот способ:** SQLite — стандарт для структурированных данных; внешняя память — для доступа пользователя к бэкапам.
•	**Как обеспечивается:**
–	Сохранность: Использование `FileChannel` для быстрого и безопасного копирования.
–	Корректность: Проверка существования папок перед записью.
